# STOBA 95 Elections

Closed voting platform for STOBA 95 association members. See
[voting-platform-plan.md](voting-platform-plan.md) for decisions and architecture.

## Structure

- `server/` — Express + TypeScript API (auth, votes, turnout, admin), sessions
  stored in Postgres via `connect-pg-simple`.
- `client/` — React + TypeScript (Vite) voter-facing UI.
- `db/schema.sql` — Postgres schema (members, roles, nominees, votes, turnout, admins).

## Local setup

1. Create a Postgres database and copy `server/.env.example` to `server/.env`,
   filling in `DATABASE_URL` and a random `SESSION_SECRET`.
2. Load the schema:
   ```
   psql "$DATABASE_URL" -f db/schema.sql
   ```
3. Install and run the server:
   ```
   cd server
   npm install
   npm run dev
   ```
4. Copy `client/.env.example` to `client/.env` and install/run the client:
   ```
   cd client
   npm install
   npm run dev
   ```
5. Create at least one admin (no signup UI by design):
   ```
   cd server
   npm run create-admin -- admin <password>
   ```
   The admin panel lives at `/admin` (e.g. http://localhost:5173/admin in dev).

## Deploying to Render

This repo is set up to deploy as a **single Render Web Service** — the
server builds the client and serves it (with an SPA fallback for `/admin`)
alongside the API, so there's one URL and no cross-origin cookie issues.

1. In Render: **New → Blueprint**, point it at this repo. `render.yaml` at
   the root defines the web service and a Postgres database together —
   Render creates both from one confirmation.
2. First deploy: the blueprint's `preDeployCommand` runs `npm run migrate`
   automatically, applying `db/schema.sql` to the new database. No manual
   DB step needed.
3. Create the first admin via Render's **Shell** tab on the web service:
   ```
   npm run create-admin -- admin <a-real-password>
   ```
4. Load the member roster and nominees the same way you would locally —
   through the admin panel, or by running an issuance script via the Shell.

`SESSION_SECRET` is auto-generated by the blueprint. `DATABASE_URL` is
wired from the Postgres instance automatically. Both are Render **starter**
plan (not free tier) per the plan's guidance on avoiding idle spin-down and
the free Postgres 30-day expiry during the live election window.

## Notes

- Ballot secrecy: `votes` rows carry no member reference; `turnout` only
  records whether a member voted per role, enforced one-per-role by its
  primary key `(member_id, role_id)`.
- Per-candidate results are only computed in `/api/admin/roles/:id/results`
  (admin) and `/api/results` (members, once closed) — never while a role's
  `is_open` is true.
- A role auto-closes as soon as every eligible member has voted, or when its
  scheduled `closes_at` passes — whichever happens first (see
  `server/src/lib/roleClosing.ts`).
